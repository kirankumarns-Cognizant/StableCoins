# UI specification and implemented screens

React + TypeScript is the connected application. Step 9 replaces the starter;
[screen inventory, API bindings, identity, configuration and recovery](32-CONNECTED-REACT-WORKSPACE.md)
are the current implementation specification. The independent offline HTML
prototype is illustrative and is not backend or blockchain evidence.

| Screen | Navigation | Main capability |
|---|---|---|
| Sign in | App entry | Configured identity PKCE or existing verified access token |
| Overview | Overview | Owned corporate accounts, policy, latest 50 payments, older-payment lookup |
| Initiate payment | New payment | Confirmed structured USD intent, outcome, fee cap, deadline, priority |
| Payment intent and routing | Payment - Intent & routing | Preparation, seven signals, deterministic ranking, actual model record and tools |
| Treasury | Payment - Treasury readiness | Captured test USDC/ETH, reservations and estimated gas |
| Independent approval | Payment - Quote & approvals | Immutable quote/version and distinct verified actors |
| Journey | Payment - Execution journey | Explicit execution command, pinned reference and audited transitions |
| Blockchain transaction | Payment - Blockchain evidence | Mode, bound hash, receipt fees, confirmations and public explorer |
| Ledger/reconciliation | Payment - Ledger & reconciliation | Immutable double-entry journals, exact per-asset balance and report/findings |
| Optional bank payout | Payment - Optional fiat payout | Simulated Visa/off-ramp status or wallet-only outcome |

The primary amount is USD 10,000. USDC moves to the beneficiary wallet; ETH pays
gas. Supported intent paths are AUTO, STABLECOIN and STABLECOIN_PLUS_VISA. A pure
Visa payment is not offered by this stablecoin intent UI. Funding, conversion,
compliance, FX, Visa and beneficiary fiat credit are explicitly simulated.

Server membership grants PAYMENT_OPERATOR/PAYMENT_APPROVER; narrative finance,
treasury and auditor personas are not separate security grants. There is no
client-side role selector, signer, mutation retry loop or financial posting tool.
The UI includes keyboard focus states, labels, responsive navigation/tables,
status/error announcements, immutable review selection and explicit evidence export.
See the [screen-by-screen demonstration](29-PROTOTYPE-EXECUTION-RUNBOOK.md) for
purpose, role, context before action, exact clicks and expected/observed evidence.
Expanded operational administration remains step 10; final live captures step 11.
